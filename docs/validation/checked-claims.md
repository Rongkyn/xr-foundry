# Checked claims register

This register lists every kind of claim the repository makes about itself and
states, for each, whether a machine checks it and which function, test, or CI job
does so. The repository is meant to run as a process that decides what merges
rather than a person who is trusted; that only works if no claim by any Agent or
person is assumed correct. A reader, a validator, or a merge verdict must be able
to tell a fact the process re-derives from a fact someone wrote down. Names below
are the real ones: `validate_*` and `check_*` functions live in
[`scripts/validate_repository.py`](../../scripts/validate_repository.py) and
[`scripts/merge_readiness.py`](../../scripts/merge_readiness.py), `test_*`
names live under [`tests/`](../../tests/), and job names come from
[`.github/workflows/`](../../.github/workflows/).

**Self-declared** means exactly this: the repository contains the claim, nothing in
the validator, the tests, or CI re-derives it, and a reader who relies on it must
verify it independently. A passing repository contract and a `ready` merge verdict
do not vouch for a self-declared claim; they prove only the machine-checked rows
on the merged tree. Every machine-checked row also names what its check does not
prove, because most checks bind structure and cross-references, not truth: a
receipt that is internally consistent and hash-bound to a public commit is still a
file someone wrote, and no check here proves that a Unity Editor produced it.

## Known gaps

The most consequential self-declared claims a machine could check next, ordered by
risk to the process-decides principle:

1. **Live deliberation records are structure-checked, and now discovery-bound, but not yet commit-attributed.** `validate_live_deliberation_records` re-derives every live record's schema, window, decision timing, mandate validity, and objection state, so a wrong window, an impossible `decided_at`, or a lazy-consensus resolution under a dead mandate or over an objection fails the repository contract. `check_governance_boundary` no longer needs `--deliberation-record` passed by hand: when it is absent, `discover_deliberation_records` finds every file added or modified under `docs/governance/deliberations/` in the candidate's own changed files, and the governance boundary is evaluated against it (one candidate exactly as the explicit option would, several by requiring at least one that authorises the change), so the CI `merge-readiness` job now binds a governance change in a pull request to the record that authorises it without a separate flag. What remains: an open record whose window has closed is not surfaced because the validator has no warnings channel; nothing proves that a lazy-consensus commit was made by the mandated Agent rather than by anyone editing the file; discovery binds by path only, so nothing cross-references a discovered record's content against the governed paths it claims to authorise; and evidence URLs are checked for existence in the tree, never for content. Binding a resolution commit to the mandate's branch patterns would close the second.
2. **Independent human review is informational in CI.** `--reviews-informational` means a routine change on a mandated branch reaches `process_merge_eligible` with zero reviews. If this is intended (lazy consensus for routine work), the register and `GOVERNANCE.md` should say so explicitly; otherwise drop the flag or gate it on decision class.
3. **GitHub-side enforcement is invisible.** Whether `merge-readiness` and `repository-contract` are required checks and whether auto-merge is enabled cannot be observed from the tree. A read-only step that fetches the branch protection or rulesets via the REST API and compares them with a committed expectation would turn this into a check.
4. **Coverage-map clause semantics and audit commit.** `validate_coverage_map_claims` now proves that every named test, assembly, and count exists and agrees, but a test that exists is not a test that exercises its clause, and `audited_at_commit` is never bound to a public-reachable SHA (the localization map records `staging`). Binding the commit, and requiring each `covered` clause to cite a contract phrase that appears in the test body, would close the remaining gap.
5. **Some source manifests remain self-declared behind an allowlist.** `validate_family_source_manifests` now checks every other family's `source-manifest.json` for schema shape, required admission fields, non-public markers, contract pairing, and a not-fetched review note, and `validate_api_surface_inventories` now compares the Interaction, Persistence, and Settings `api-surface.md` type lists (and their stated counts) with the `public class/struct/enum/interface/record/delegate` declarations in each family's `Runtime/**/*.cs`, so the three API surface inventories are no longer purely self-declared. What remains: `FAMILY_SOURCE_MANIFEST_UNVERIFIED_CLAIMS` still allowlists Design Language's missing verification contract, Foundations' missing source manifest, and the missing review note in Interaction, Persistence, Settings, and Design Language; fixing those manifests instead of allowlisting them would close the rest.
6. **Lesson dispositions are trusted.** An `adopted` status is never compared with code or tests; a family can answer every lesson with a sentence. A disposition could be required to cite a test name or contract clause that the coverage-map rule then verifies.
7. **Release tags are not bound.** The batch registry's `release_tag` is checked against the batch file only; nothing proves the tag exists or points at the evidence commit. A rule can compare `git tag --points-at` against the profile's `commit_sha` when the tag is fetched.
8. **Catalog evidence flags are free text.** `independent_compile`, `git_url_install`, and `device_evidence` could be derived from verified profiles and device receipts instead of typed.
9. **Reference-catalog maturity agreement is now checked for every package artifact.** `validate_reference_package_coherence` binds each reference’s explicit `package_id` and path to the package catalog and compares maturity, independently of Inventory standard files. `test_reference_package_coherence_rejects_maturity_drift_for_every_package` mutates every live package reference and rejects both changed and missing maturity; unknown package IDs and swapped paths also have regression tests. This closes the former non-Inventory gap, but does not prove that a maturity state is earned.
10. **Evidence provenance.** Every Editor and device receipt is structure- and hash-checked, never origin-checked. The unity-consumer-tests job could publish a signed attestation of its NUnit result that a profile then references, so at least CI-produced evidence carries a provenance the validator can verify.

## How to update this register

Any new validator rule, merge-readiness check, CI job, or new kind of claim-bearing
artifact adds or amends a row here in the same change, naming the function, test,
or job exactly as it appears in the code and stating what the check does not
prove. When a self-declared row becomes machine-checked, move its text from the
"Still self-declared" column to the "What the check proves" column rather than
deleting it, so the history of what was once trusted stays readable. This register
is documentation: nothing validates it, its row counts, or its function names, and
a reader should grep for any name here before relying on it.
